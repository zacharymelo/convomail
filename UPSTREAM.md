# Core changes this module works around

Convomail is built as a custom module first, with the aim of proposing webmail for Dolibarr core
(design: "Dolibarr Core Webmail: Design & Scaffolding"). Each item below is a gap the module had to
work around. Each one is a small, separate core pull request to make before proposing the module itself.

| # | Gap | Workaround in convomail | Core change to propose |
|---|-----|-------------------------|------------------------|
| 1 | The conversation pages (`societe/messaging.php`, `contact/messaging.php`, `projet/messaging.php`) only run the `doActions` hook | "Send email" buttons sit on the card pages; "Reply" is on the event card | Run `addMoreActionsButtons` (or a `messagingActions` hook) on the three messaging pages, plus a per-item hook in `show_actions_messaging()` |
| 2 | `CMailFile` does not expose the built message | Force swiftmailer mode for the `convomail` send context and read `$mailfile->message->toString()` | Store the raw MIME after `sendfile()` for every send mode, or add an option to IMAP APPEND sent mail to a folder |
| 3 | `CMailFile::$message` is a dynamic property (deprecated in PHP 8.2+) | Guarded with `isset()` / `method_exists()` | Declare the property |
| 4 | No per-user OAuth flow; tokens are created from an admin page (`admin/oauthlogintokens.php`) even though `llx_oauth_token` has `fk_user`. Core's callbacks store one token per app (`Google-<name>`), and `DoliStorage` ignores `fk_user` on store and retrieve | Since 0.5.0: own consent page and callback (`oauth.php`) using core's apps and phpoauth services; one `llx_oauth_token` row per account (`<Service>-convomail<id>`) with `fk_user` set by the module; `CMailFile` reads it through in-memory `MAIN_MAIL_SMTPS_OAUTH_SERVICE_CONVOMAIL` | A user-facing "Connect with Google / Microsoft" flow storing tokens with `fk_user`, and `CMailFile` reading a user's token |
| 5 | No index on `llx_actioncomm.email_msgid` | Module adds `idx_actioncomm_email_msgid` in `sql/llx_convomail_zactioncomm.key.sql` | Add the index in core SQL and the migration file |
| 6 | Reply matching lives inside `EmailCollector::doCollectOneCollector()` | Phase 1 only sends; it sets the trackid in the Message-ID so Email Collector can link replies | Extract matching (sender to contact/third party, trackid, In-Reply-To) into a shared class both modules call |
| 7 | `References` with several ids fails with Swift Mailer's `addIdHeader()` when passed a space-separated string | Phase 1 sends the parent Message-ID only | Accept an array, or split the string, in `CMailFile` |
| 8 | `email_admin_prepare_head()` calls `complete_head_from_modules()` in `'remove'` mode only, so modules cannot add a tab to Home > Setup > Emails | Module declares an `email_admin` tab (shown once patched) and its setup page joins that tab bar when the tab exists; [patches/dolibarr-email-admin-module-tabs.patch](patches/dolibarr-email-admin-module-tabs.patch) | Call it in `'add'` mode too, as `company_admin_prepare_head()` does. Branch `new-email-admin-module-tabs` prepared, PR held for review ([patches/README.md](patches/README.md)) |
| 9 | Menu entries can't depend on a per-user setting: `dol_eval()` only allows `isModEnabled`, `hasRight`, `getDolGlobal*`, `$user->admin`..., and `loadRights()` rebuilds `$user->rights` right before `loadMenu()` with no hook in between | The Mailbox tab shows to everyone with the "use own mail accounts" right; users without an account get a prompt to add one | Allow `getDolUserInt`/`getDolUserString` in menu conditions, or add a hook after `loadRights()` and before `loadMenu()` in `main.inc.php` |
| 10 | In swiftmailer mode, `CMailFile` sends each pasted image (`src="data:..."`, converted by `MAIN_MAIL_ADD_INLINE_IMAGES_IF_DATA`) three times: embedded from `html_images`, embedded again from `images_encoded`, and attached through `$filename_list` | `ConvomailTransport::dedupePastedImages()` keeps the embedded copy the HTML references and drops the others before sending | Embed each converted image once and don't add `cidfromdata` images to the attachment list in the swiftmailer branch |
| 11 | Email Collector's example collectors (Collect_Responses_In/_Out...) are only created at module activation, disabled, and collectors have no owner | `ConvomailCollector` creates per-mailbox copies (refs `CONVOMAIL<id>_IN/_OUT`) and sets the events' owner with action parameters (`userownerid=SET:<id>`) | A "create from template" action, and an optional owner (`fk_user`) used for recorded events |
| 12 | Email Collector refreshes an OAuth token only with `OAUTH_<oauth_service>_ID/_SECRET` constants, so a per-user token (service `Google-<key>`) can't be refreshed with the app's own credentials | Convomail's cron job *Refresh Convomail sign-in tokens* keeps the tokens valid before collectors run | Resolve the app credentials from the token row (or a mapping), not from the service name |
| 13 | `EmailCollector::doCollect()` handles at most ~100 collectors per cron run (`fetchAll` default limit) | Documented (about 50 mailboxes with two collectors) | Page through all active collectors |
| 14 | The bundled OAuth library prints the provider's error (`AbstractService::refreshAccessToken`, "@CHANGE LDR") | Output captured around the refresh (`ConvomailOAuth::accessToken()`) and logged | Log or throw instead of printing |
| 16 | No element => documents folder helper: `getMultidirOutput()` is wrong for supplier invoices (needs `get_exdir(id,2)` + ref) and contacts (`societe/contact/<id>`), and `dol_check_secure_access_document(…, 'write')` has no branch for tickets or supplier proposals | `ConvomailTargets::uploadDir()` and `canWrite()` mirror each record's Documents tab | One core function returning a record's documents folder and write right |
| 17 | Email Collector's "join piece" (`recordjoinpiece`) files supplier-invoice attachments outside the invoice's real folder (no `get_exdir` levels) and matches on `ref_client`, a field supplier invoices don't have | Convomail files attachments itself, from the user's choice | Use the record's own Documents folder and `ref_supplier` |
| 15 | `ai/ajax/generate_content.php` answers HTTP 200 when the AI provider can't be reached: `http_response_code($generatedContent['code'])` with no code. Core's mail form then pastes "Error returned by API call: …" into the message | Compose's AI tools treat answers starting with core's error texts ("Error…", "Quota or allowed period exceeded") as errors and show them beside the tools | Answer 502 (or the provider's code) on every error |
| 18 | The AI module's `PrivacyGuard` (develop, 2026-10-25) masks only the first group of an IBAN written with spaces (`IBAN [[REF_…]] 3000 6000 0112 3456 7890 189`), so most of the bank account still reaches the AI provider | Before reading an invoice with the AI, `ConvomailInvoiceAi::scrub()` removes IBANs, BICs, labelled account and phone numbers and emails itself, whatever the redaction setting | Match IBANs with their spaces (and BIC / account numbers after their label) in `PrivacyGuard::mask()` |
